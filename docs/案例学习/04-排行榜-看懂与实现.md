# 案例4 · 积分排行榜（ZSet）

> 技术方案：ZSet（Set + 分数）自动排序
> 学什么：**什么时候用 ZSet**（要排序、要排名、要 TopN）
>
> 脚手架见《00-总纲》，本文只讲增量。

---

# Part A · 看懂版

## A1. 核心：为什么排行榜用 ZSet？（选型题）

ZSet = Set（成员唯一）+ Score（分数），**按分数自动排序**。

| 用别的结构 | 问题 |
|-----------|------|
| List | 要自己排序、自己维护分数，插入删除成本高 |
| Set | 无分数概念，无法排序 |
| Hash | 存分数后还要额外排序逻辑 |
| ✅ ZSet | ZINCRBY 原子加分、ZREVRANGE 取 TopN、ZREVRANK 查排名，一条命令搞定 |

存储结构：`rank:score` 是一个 ZSet，member=userId，score=积分。

## A2. 逐行翻译（5 个方法 = 5 条命令）

```java
addScore(userId, score)     // ZINCRBY rank:score 10 user:1（原子累加，不覆盖）
    stringRedisTemplate.opsForZSet().incrementScore(key, String.valueOf(userId), score);

getRank(userId)             // ZREVRANK rank:score user:1（从高到低的名次，0 起）
    stringRedisTemplate.opsForZSet().reverseRank(key, String.valueOf(userId));
    // 返回 0 起下标，展示时 +1 = 第几名；未上榜返回 null

getScore(userId)            // ZSCORE rank:score user:1（查某成员分数）
    stringRedisTemplate.opsForZSet().score(key, String.valueOf(userId));

getTopN(n)                  // ZREVRANGE rank:score 0 n-1（从高到低取前 N 名）
    stringRedisTemplate.opsForZSet().reverseRange(key, 0, n - 1);

getTopNWithScores(n)        // ZREVRANGE WITHSCORES（前 N 名 + 分数，做榜单展示）
    stringRedisTemplate.opsForZSet().reverseRangeWithScores(key, 0, n - 1);
```

## A3. 为什么加分用 `incrementScore`（ZINCRBY）而不是 `add`（ZADD）？

- `ZADD`：**覆盖**原有分数（适合"设置"分数）；
- `ZINCRBY`：**原子累加**（适合"积分增长"场景，不会覆盖）。

## A4. 测试剧本

```java
addScore(1, 100) / addScore(2, 50) / addScore(3, 200)  // 三人积分
getScore(1)      // 100
getRank(3)       // 1（200分最高）
getRank(1)       // 2
getTopN(10)      // [3, 1, 2]
```

## A5. 记忆锚点

- `incrementScore`=ZINCRBY、`reverseRank`=ZREVRANK、`score`=ZSCORE、`reverseRange`=ZREVRANGE、`reverseRangeWithScores`=ZREVRANGE WITHSCORES。
- **选型**：要「按分数排序 + 排名 + TopN」→ ZSet。
- `reverse*` 开头 = 从高到低（reverse 反序），这是 ZSet 方法名里最容易懵的地方。

# Part B · 从0实现版

## B1. 需求

> 用户积分排行榜：加分、查分数、查排名、取 TopN（含分数）。

## B2. 内心独白

> 榜单本质是「排序」。Set 不能排序，List 要自己排。
> 用 **ZSet**：给每个 userId 挂一个「分数」，Redis 自动按分数排序，加分、排名、TopN 都是现成命令。

## B3. 手写代码

```java
@Service
@RequiredArgsConstructor
public class RankService {

    private final StringRedisTemplate redis;
    private static final String KEY = "rank:score";

    public void addScore(Long userId, double score) {
        // ZINCRBY：原子累加
        redis.opsForZSet().incrementScore(KEY, String.valueOf(userId), score);
    }

    public Long getRank(Long userId) {
        // ZREVRANK：从高到低的名次（0 起），+1 才是第几名
        Long rank = redis.opsForZSet().reverseRank(KEY, String.valueOf(userId));
        return rank == null ? null : rank + 1;
    }

    public Double getScore(Long userId) {
        // ZSCORE
        return redis.opsForZSet().score(KEY, String.valueOf(userId));
    }

    public List<String> getTopN(int n) {
        // ZREVRANGE：从高到低取前 N 名
        Set<String> members = redis.opsForZSet().reverseRange(KEY, 0, n - 1);
        return members == null ? List.of() : members.stream().toList();
    }
}
```

## B4. 与案例3 的区别（记住这一句）

> Set 只关心「在不在集合里」，ZSet 在 Set 基础上给每个成员挂了个**分数**，自动排序。**要排序就 ZSet，只去重判存在就 Set。**

## B5. 自测标准

> 能说出「排行榜为什么用 ZSet（自动排序）而不是 List（要自己排）」，并能区分 `incrementScore`（累加）和 `add`（覆盖），案例4 就掌握了。
