# 案例3 · 点赞统计（Set）

> 技术方案：Set 存点赞用户，集合运算求共同点赞
> 学什么：**什么时候用 Set**（去重 + 判存在 + 计数 + 交集）
>
> 脚手架见《00-总纲》，本文只讲增量。

---

# Part A · 看懂版

## A1. 全景流程图

```
POST /api/like/1/1  (用户1 点赞 商品1)
   │
   ▼
LikeService.like(1, 1)
   │
   └─ SADD like:product:1 "1"     → 返回 1=新增成功，0=已点过（重复点赞自动去重）
```

存储结构：`like:product:1` 是一个 Set，成员是 userId 字符串。

## A2. 核心：为什么点赞用 Set？（选型题）

点赞的核心动作是「点赞/取消/判断是否已赞/统计数量」，本质是**集合操作**：

| 用别的结构 | 问题 |
|-----------|------|
| String 计数（INCR） | 只能知道总数，**无法知道「谁」点过赞，无法取消点赞** |
| List | 元素可重复，**无法去重**，无法 O(1) 判断是否存在 |
| ✅ Set | 元素唯一（SADD 自动去重）、SISMEMBER O(1) 判存在、SCARD O(1) 计数、SINTER 求交集 |

## A3. 逐行翻译（5 个方法 = 5 条命令）

```java
like(productId, userId)       // SADD：加成员，返回 1=成功 / 0=已存在（重复）
    stringRedisTemplate.opsForSet().add(key, String.valueOf(userId));     // SADD

unlike(productId, userId)     // SREM：删成员，返回 1=删成功 / 0=本来就没有
    stringRedisTemplate.opsForSet().remove(key, String.valueOf(userId));  // SREM

isLiked(productId, userId)    // SISMEMBER：O(1) 判断成员在不在
    stringRedisTemplate.opsForSet().isMember(key, String.valueOf(userId));// SISMEMBER

likeCount(productId)          // SCARD：统计成员数（点赞总数）
    stringRedisTemplate.opsForSet().size(key);                            // SCARD

commonLikers(pid1, pid2)      // SINTER：两个商品点赞用户的交集（共同点赞）
    stringRedisTemplate.opsForSet().intersect(key1, key2);                // SINTER
```

## A4. 测试剧本

```java
like(1,1) / like(1,2) / like(1,3)   // 3 人点赞商品1
like(1,1)                            // 重复点赞 → 返回 false（SADD 去重）
isLiked(1,1)                         // true
likeCount(1)                         // = 3
unlike(1,1)                          // 取消 → likeCount = 2
commonLikers(1, 2)                   // 商品1∩商品2 的共同点赞用户
```

## A5. 记忆锚点

- `add`=SADD、`remove`=SREM、`isMember`=SISMEMBER、`size`=SCARD、`intersect`=SINTER。
- **选型**：去重 + 判存在 + 计数 + 交集 → Set。

# Part B · 从0实现版

## B1. 需求

> 用户点赞商品：点赞、取消点赞、判断是否已赞、统计点赞数、求两个商品的共同点赞用户。

## B2. 内心独白

> 点赞要能「知道谁点的、能取消、能判存在、能统计、能算交集」。
> 这是个「集合」问题，不是「计数」问题（String 只知道总数）也不是「队列」问题（List 能重复）。
> 用 **Set**：成员唯一天然去重，一条命令判存在、计数、求交集全搞定。

## B3. 手写代码

```java
@Service
@RequiredArgsConstructor
public class LikeService {

    private final StringRedisTemplate redis;

    public boolean like(Long productId, Long userId) {
        // SADD：返回 1 新增成功 / 0 已存在（重复点赞）
        Long added = redis.opsForSet().add("like:product:" + productId, String.valueOf(userId));
        return added != null && added > 0;
    }

    public boolean unlike(Long productId, Long userId) {
        // SREM
        Long removed = redis.opsForSet().remove("like:product:" + productId, String.valueOf(userId));
        return removed != null && removed > 0;
    }

    public boolean isLiked(Long productId, Long userId) {
        // SISMEMBER
        return Boolean.TRUE.equals(
            redis.opsForSet().isMember("like:product:" + productId, String.valueOf(userId)));
    }

    public Long likeCount(Long productId) {
        // SCARD
        Long count = redis.opsForSet().size("like:product:" + productId);
        return count == null ? 0L : count;
    }

    public Set<String> commonLikers(Long p1, Long p2) {
        // SINTER
        return redis.opsForSet().intersect("like:product:" + p1, "like:product:" + p2);
    }
}
```

## B4. 与案例1/2 的区别（记住这一句）

> 案例1 是「一个 key 存一个值」（String），案例2 是「一个 key 存字段表」（Hash），案例3 是「一个 key 存**一堆不重复的值**」（Set）。判断「在不在集合里」是 Set 的独门绝活。

> 能说出「点赞为什么不用 String 计数 / 不用 List」，并能默写出 SADD/SREM/SISMEMBER/SCARD/SINTER 五个方法名，案例3 就掌握了。
