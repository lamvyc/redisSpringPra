# 案例2 · 商品详情缓存（Hash）

> 技术方案：Hash 存商品对象，字段级读写
> 学什么：**什么时候用 Hash 而不是 String**（面试高频选型题）
>
> 脚手架（建表/实体/Mapper/Controller）见《00-总纲》，本文只讲与案例1 的**增量**。

---

# Part A · 看懂版

## A1. 全景流程图

```
GET /api/product/1
   │
   ▼
ProductCacheService.getProductById(1)
   │
   ├─ ① 判断 key 存在吗 ──→ hasKey("product:detail:1")              = EXISTS product:detail:1
   │       │ 存在 ↓
   │       └─ ② 取出全部字段 ──→ entries(key)                        = HGETALL product:detail:1
   │               （把 field→value 组装回 Product 对象，直接返回）
   │
   └─ 不存在 → ③ 查库 → ④ putAll 一次性写入 Hash → ⑤ expire 设过期
                   = HMSET product:detail:1 id 1 name ... price ...
                   = EXPIRE product:detail:1 3600
```

## A2. 核心：为什么商品用 Hash 而不是 String？（选型题，背下来）

| | String（案例1 存用户） | Hash（案例2 存商品） |
|---|---|---|
| 存法 | 整个对象序列化成**一个 JSON** | 每个字段存成**一个 field** |
| 改价格 | 要 GET 整个 JSON → 反序列化 → 改 → SET 回去 | 只 `HSET price` 一个字段 |
| 并发改 | 后写覆盖先写，**丢更新** | 只动各自字段，**互不影响** |

**一句话**：整体读写的对象用 String；**需要频繁改某个字段**的对象用 Hash（商品价格、库存、点赞数等）。这就是案例2 存在的全部意义。

## A3. 逐行翻译

```java
// getProductById —— 读
if (Boolean.TRUE.equals(stringRedisTemplate.hasKey(key))) {   // EXISTS product:detail:1
    Map<Object, Object> entries = stringRedisTemplate.opsForHash().entries(key);  // HGETALL
    return toProduct(entries);   // 把 field→value 手动组装回 Product
}
// 未命中：查库
stringRedisTemplate.opsForHash().putAll(key, toMap(product));  // HMSET：一次性写所有字段
stringRedisTemplate.expire(key, CACHE_TTL);                    // EXPIRE 3600
```

```java
// updateProduct —— 写（字段级更新，核心亮点）
Map<String, String> changedFields = new HashMap<>();
if (price != null) changedFields.put("price", price.toPlainString());  // 只收集变化的字段
productRepository.save(product);                              // 先改 DB
stringRedisTemplate.opsForHash().putAll(key, changedFields);  // HSET：只改变化的字段
```

```java
// addProductTag —— 动态扩展字段（Hash 的优势）
stringRedisTemplate.opsForHash().put(key, "tags", tag);       // HSET product:detail:1 tags "旗舰"
// 不用改表结构、不用迁移，直接加字段
```

## A4. 为什么这里用 StringRedisTemplate 而不是 RedisTemplate？

Hash 的 field/value 都是纯字符串（`"price"` → `"8999.00"`），`StringRedisTemplate` 不做 JSON 序列化，redis-cli 里 `HGETALL product:detail:1` 直接可读。用 `RedisTemplate` 的话 value 会被序列化成带引号的 JSON，字段不可读。

## A5. 测试剧本

```java
getProductById(1L)          // 首次：查库 → HMSET 写 Hash
updateProduct(1L, 7999)     // 改 price 字段 → HSET price
getProductById(1L)          // 再查：从 Hash 读，价格已更新
addProductTag(1L, "旗舰")    // HSET tags 动态加字段
```

## A6. 记忆锚点

- `hasKey`=EXISTS、`entries`=HGETALL、`put`=HSET、`putAll`=HMSET、`expire`=EXPIRE。
- **选型**：整体读写用 String，频繁改单个字段用 Hash。

# Part B · 从0实现版

## B1. 需求

> 查询商品详情；支持**只更新价格**这一个字段，不用重写整个缓存。

## B2. 内心独白（先想清楚再用什么结构）

> 商品字段多（名称/价格/库存/描述…），而改价格是高频操作。
> 如果用案例1 的 String，改价格要「GET 整个 JSON → 改 → SET 回去」，并发下会丢更新。
> 我想要的是「只改 price 字段」，所以用 **Hash**：一个字段一个 field，改哪个 field 就 HSET 哪个。

## B3. 手写代码（只写与案例1 不同的 Service）

```java
@Service
@RequiredArgsConstructor
public class ProductCacheService {

    private final StringRedisTemplate redis;      // 注意：用 StringRedisTemplate
    private final ProductMapper productMapper;    // 你的 MyBatis-Plus Mapper

    public Product getById(Long id) {
        String key = "product:detail:" + id;

        // EXISTS 判断 key 在不在
        if (Boolean.TRUE.equals(redis.hasKey(key))) {
            // HGETALL 取出全部字段，手动组装回 Product
            Map<Object, Object> entries = redis.opsForHash().entries(key);
            return toProduct(entries);
        }

        Product p = productMapper.selectById(id);
        if (p == null) throw new RuntimeException("商品不存在");

        // HMSET 一次性写所有字段 + EXPIRE 设过期
        redis.opsForHash().putAll(key, toMap(p));
        redis.expire(key, Duration.ofHours(1));
        return p;
    }

    public Product updatePrice(Long id, BigDecimal price) {
        // 先改 DB
        Product p = productMapper.selectById(id);
        p.setPrice(price);
        productMapper.updateById(p);

        // 只改变化的字段：HSET product:detail:1 price 7999
        redis.opsForHash().put("product:detail:" + id, "price", price.toPlainString());
        return p;
    }

    // 工具：Product ↔ Map
    private Map<String, String> toMap(Product p) {
        Map<String, String> m = new HashMap<>();
        m.put("id", String.valueOf(p.getId()));
        m.put("name", p.getName());
        m.put("price", p.getPrice().toPlainString());
        return m;
    }
    private Product toProduct(Map<Object, Object> e) {
        return new Product(
            Long.valueOf((String) e.get("id")),
            (String) e.get("name"),
            new BigDecimal((String) e.get("price")));
    }
}
```

## B4. 与案例1 的唯一区别（记住这一句）

> 案例1 用 `opsForValue` 整体存 String；案例2 用 `opsForHash` 按字段存。**改一个字段时，Hash 只 HSET 那一个 field，不用重写整个对象。**

## B5. 自测标准

> 能说清「商品改价格，为什么用 Hash 比 String 好」（字段级更新、并发不丢更新），并能手写出 `putAll` + `put` 两个关键调用，案例2 就掌握了。
