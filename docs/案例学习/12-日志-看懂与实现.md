# 案例12 · 日志使用全流程（@Slf4j + Logback）

> 技术方案：Lombok @Slf4j + SLF4J 门面 + Logback 实现
> 学什么：**怎么打日志、5 个级别、占位符、日志配置**（和 Redis 无关，是 Spring Boot 基础能力）
>
> 说明：本项目 docs 里称它为「案例11」，为避免和 Spring Cache 文档编号冲突，这里记为 12。它是纯 Java/Spring 知识，不涉及 Redis。

---

# Part A · 看懂版

## A1. 全景图：一次日志是怎么"流"出来的

```
你的代码：log.info("用户登录成功，userId={}", id)
   │
   ▼
@Slf4j 编译时生成：private static final Logger log = LoggerFactory.getLogger(LogDemoService.class)
   │
   ▼
SLF4J（门面接口，只管"调用"，不管"实现"）
   │
   ▼
Logback（实现，真正把日志写出去）
   │
   ├─ 按级别过滤：INFO 级别配置下，只输出 INFO/WARN/ERROR
   ├─ 按 pattern 格式化
   └─ 输出到 appender（控制台 / 文件）
```

**核心：SLF4J 是"门面"（接口），Logback 是"实现"。** 你代码里只依赖 SLF4J，换实现（比如换成 Log4j2）不用改代码。Spring Boot 默认就带 Logback，无需额外依赖。

## A2. 逐行翻译：LogDemoService 的 4 个方法

### ① demoLevels —— 5 个级别 + 占位符

```java
@Slf4j                      // Lombok 编译时生成 log 对象，不用自己写
public class LogDemoService {
    log.trace("...");       // 最细，追踪每步，生产几乎不开
    log.debug("...");       // 调试信息（缓存命中/未命中、SQL 参数），开发用
    log.info("...");        // 关键业务节点，生产默认开到这级
    log.warn("...");        // 潜在问题但不影响主流程（如降级、重试）
    log.error("...", e);    // 错误，必须记录，且带异常堆栈
}
```

**5 个级别（由低到高）：`TRACE < DEBUG < INFO < WARN < ERROR`**
**核心规则：只有「大于等于配置级别」的日志才输出。** 配置为 INFO，就只输出 INFO/WARN/ERROR。

### ② 占位符 {} 为什么比字符串拼接好？（面试点）

```java
log.debug("userId=" + userId + ", name=" + name);  // ❌ 即使 DEBUG 被过滤，拼接仍执行，浪费性能
log.debug("userId={}, name={}", userId, name);     // ✅ 级别不满足时，底层不拼接，零开销（惰性求值）
```

### ③ demoError —— error 必须带异常对象（最重要的一条）

```java
log.error("计算异常，msg={}", e.getMessage(), e);   // ✅ 异常作为最后一个参数 → 打印完整堆栈
log.error("出错了：" + e.getMessage());              // ❌ 只有一句话，没堆栈，找不到出错在哪行
```

**记忆锚点**：`log.error("msg", e)` 一定要把异常对象 `e` 作为最后一个参数，否则丢堆栈 = 白记。

### ④ demoBusinessFlow —— 用 orderNo 贯穿整个流程

```java
log.info("========== 开始处理订单 orderNo={} ==========", orderNo);
// ... 校验 / 查库存 / 调支付 ...
log.info("========== 结束处理订单 orderNo={} ==========", orderNo);
```

**实战最佳实践**：用同一个 `traceId / 订单号` 贯穿所有日志，方便在海量日志里串起一次完整调用。

## A3. logback-spring.xml 三个核心概念

| 概念 | 作用 | 对应配置 |
|------|------|---------|
| **pattern** | 日志格式 | `%d{时间} %-5level [%thread] %logger{40} - %msg%n` |
| **appender** | 输出到哪（控制台/文件） | `ConsoleAppender` / `RollingFileAppender` |
| **logger** | 按包/类设级别 | `<logger name="com.dev.redisspringpra" level="debug">` |

### 关键配置解读

```xml
<!-- 只给本项目包开 debug，其余（Spring/Hibernate）用 info，避免被框架日志刷屏 -->
<logger name="com.dev.redisspringpra" level="debug" additivity="false">
    <appender-ref ref="CONSOLE"/>
    <appender-ref ref="FILE"/>
</logger>

<!-- 单独把 LogDemoService 调到 trace，演示 trace 如何开启 -->
<logger name="com.dev.redisspringpra.service.LogDemoService" level="trace"/>

<!-- 根日志：兜底，所有没被单独命中的包走这里 -->
<root level="info">
    <appender-ref ref="CONSOLE"/>
    <appender-ref ref="FILE"/>
</root>
```

### 文件滚动（生产排查必开）

```xml
<file>${LOG_DIR}/${APP_NAME}.log</file>                              <!-- 当前文件 -->
<fileNamePattern>${LOG_DIR}/${APP_NAME}.%d{yyyy-MM-dd}.log</fileNamePattern>  <!-- 按天生成新文件 -->
<maxHistory>30</maxHistory>      <!-- 保留 30 天 -->
<totalSizeCap>1GB</totalSizeCap> <!-- 总大小上限 -->
```

### logback-spring.xml vs logback.xml（面试点）

- `logback-spring.xml`：Spring Boot 在 application.yml **之后**加载，能用 `${}` 拿 application.yml 的配置，还能 `<springProfile>` 按环境区分。
- `logback.xml`：Logback 直接加载，加载最早，拿不到 application.yml 的东西。

## A4. 验证方式

```bash
curl "http://localhost:8080/api/log/levels?userId=1&name=张三"   # 看 info/debug/trace
curl "http://localhost:8080/api/log/error"                       # 看 error + 堆栈
curl "http://localhost:8080/api/log/flow?orderNo=xxx"            # 看带上下文的流程日志
```
控制台（和 `logs/redisSpringPra.log` 文件）会打印对应日志。

## A5. 记忆锚点

- **级别**：TRACE < DEBUG < INFO < WARN < ERROR，只有 ≥ 配置级别才输出。
- **占位符**：`log.debug("id={}", id)` 惰性求值，比拼接省性能。
- **error**：`log.error("msg", e)` 必须带异常对象，否则丢堆栈。
- **日志三要素**：pattern（格式）、appender（输出到哪）、logger（按包设级别）。

# Part B · 从0实现版

## B1. 需求

> 给自己写的 Service 加日志，能看调试信息、能记录异常、能落到文件里。

## B2. 内心独白

> 排障要靠日志。要「能打出来 + 分级别 + 能持久化到文件」。用 Lombok 的 @Slf4j 省掉手写 logger，用 logback-spring.xml 配置格式和输出位置。

## B3. 手写代码（3 步）

### 第 1 步：类上加 @Slf4j

```java
@Slf4j
@Service
public class MyService {
    public void doSomething(Long id) {
        log.info("开始处理，id={}", id);
        try {
            // 业务
        } catch (Exception e) {
            log.error("处理失败，id={}", id, e);   // 异常作最后参数
        }
    }
}
```

### 第 2 步：加 logback-spring.xml（放 src/main/resources/）

```xml
<configuration>
    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] %logger{40} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 文件输出，按天滚动 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/app.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] %logger{40} - %msg%n</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 本项目包开 debug，根开 info -->
    <logger name="com.dev" level="debug" additivity="false">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </logger>
    <root level="info">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>
</configuration>
```
