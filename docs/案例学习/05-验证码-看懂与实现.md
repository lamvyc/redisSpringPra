# 案例5 · 验证码（String + TTL + 防刷）

> 技术方案：String 存验证码，TTL 自动过期，SETNX 防刷
> 学什么：**TTL 的经典用法 + setIfAbsent（SETNX）防刷**
>
> 脚手架见《00-总纲》，本文只讲增量。

---

# Part A · 看懂版

## A1. 全景流程图

```
POST /api/captcha/send?phone=13800000001
   │
   ▼
CaptchaService.sendCaptcha(phone)
   │
   ├─ ① setIfAbsent(rateKey) 防刷   = SET user:captcha:13800000001:rate 1 NX EX 60
   │       （60 秒内已发过 → 返回 false → 抛"发送过于频繁"）
   │
   ├─ ② 生成 6 位验证码
   └─ ③ set(key, code, 5min)        = SET user:captcha:13800000001 123456 EX 300

POST /api/captcha/verify?phone=xxx&code=123456
   └─ get(key) 校验 → 通过后 delete(key) 一次性消费 = DEL
```

## A2. 核心：为什么验证码用 String + TTL？

验证码是「短生命周期的字符串」，Redis 的 TTL 让它**自动过期清理**，不用手动删。

**为什么不用 MySQL 存验证码？** 验证码高频、要过期清理，MySQL 没有 TTL 机制，还要写定时任务清理。

## A3. 逐行翻译（两个方法 = 3 个新命令）

```java
// sendCaptcha —— 发验证码
String rateKey = key + ":rate";   // 防刷 key

// setIfAbsent = SET NX EX：key 不存在才写入，并设 60 秒过期
Boolean firstTime = stringRedisTemplate.opsForValue().setIfAbsent(rateKey, "1", Duration.ofSeconds(60));
if (Boolean.FALSE.equals(firstTime)) {
    throw new BizException("发送过于频繁，请 60 秒后再试");  // 60 秒内发过 → 拒绝
}

// set(key, code, Duration) = SET ... EX：写入 + 5 分钟过期一步完成
stringRedisTemplate.opsForValue().set(key, captcha, expire);
```

```java
// verifyCaptcha —— 校验
String stored = stringRedisTemplate.opsForValue().get(key);  // GET
if (stored == null) throw new BizException("验证码已过期");   // 过期或没发过
boolean valid = stored.equalsIgnoreCase(inputCode);
if (valid) {
    stringRedisTemplate.delete(key);   // DEL：校验成功即删（一次性使用）
}
```

## A4. 三个面试点

1. **`setIfAbsent` = `SET NX EX`**：SET if Not eXists——「不存在才写入」，这是防刷的核心。为什么不用普通 `set`？普通 set 会覆盖，无法判断"60秒内是否发过"。
2. **一次性消费**：校验成功立刻 DEL，防止同一个验证码被反复使用。
3. **为什么「写入+过期」要一步完成？** 分开写（先 set 再 expire）如果中间进程挂了，验证码就永久不过期。

## A5. 测试剧本

```java
sendCaptcha(phone)       // 第一次成功，返回 6 位码
verifyCaptcha(phone, code) // 校验成功 → 消费删除
verifyCaptcha(phone, code) // 再校验 → 抛异常（已消费，一次性）
sendCaptcha(phone)       // 60 秒内再发 → 抛异常（防刷）
```

## A6. 记忆锚点

- `setIfAbsent` = `SET NX EX`（防刷）、`set(key,val,Duration)` = `SET EX`（写+过期一步）、`get`、`delete`。
- **验证码套路**：写带 TTL → 校验 → 删（一次性）；发送前用 setIfAbsent 防刷。

# Part B · 从0实现版

## B1. 需求

> 发验证码（5 分钟过期、60 秒内只能发一次）；校验验证码（一次性使用）。

## B2. 内心独白

> 验证码 = 一个手机号对应一个短命字符串。要「自动过期」→ 用 TTL；要「60 秒防刷」→ 发之前先查有没有"发过"的标记，没有才发 → 用 setIfAbsent。

## B3. 手写代码

```java
@Service
@RequiredArgsConstructor
public class CaptchaService {

    private final StringRedisTemplate redis;

    public String send(String phone) {
        String key = "user:captcha:" + phone;
        String rateKey = key + ":rate";

        // ① 防刷：SET NX EX 60，返回 false 说明 60 秒内发过
        Boolean first = redis.opsForValue().setIfAbsent(rateKey, "1", Duration.ofSeconds(60));
        if (Boolean.FALSE.equals(first)) {
            throw new RuntimeException("发送过于频繁，请 60 秒后再试");
        }

        // ② 生成 6 位码
        String code = String.valueOf(new SecureRandom().nextInt(100000, 999999));

        // ③ 写验证码 + 5 分钟过期
        redis.opsForValue().set(key, code, Duration.ofMinutes(5));
        return code;  // 真实项目这里调短信商发送，学习项目直接返回
    }

    public boolean verify(String phone, String input) {
        String key = "user:captcha:" + phone;
        String stored = redis.opsForValue().get(key);   // GET
        if (stored == null) throw new RuntimeException("验证码已过期");
        boolean ok = stored.equalsIgnoreCase(input);
        if (ok) redis.delete(key);                       // DEL 一次性消费
        return ok;
    }
}
```

## B4. 与案例1 的区别（记住这一句）

> 案例1 缓存的是「长期数据」（30 分钟保鲜）；案例5 缓存的是「短命数据」（5 分钟过期 + 一次性删除 + 防刷）。**TTL 是会话类数据的灵魂。**

## B5. 自测标准

> 能说出 `setIfAbsent` 和 `set` 的区别（前者不存在才写，后者无条件写），并能默写出「防刷 → 写码带 TTL → 校验删码」三段，案例5 就掌握了。
